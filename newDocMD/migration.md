# Миграция спецификаций

Migration поддерживает OpenSpec, Spec Kit и обычную папку документации внутри выбранного workspace: через `specrow_migrate` в MCP или `migrate` во встроенном Codex CLI.

## Безопасный порядок

1. Проверить project status для целевого проекта через доступный адаптер.
2. Определить формат источника до записи.
3. При неоднозначности или риске перезаписи сначала выполнить dry run.
4. Выполнить миграцию без `force` по умолчанию.
5. Запустить validate через тот же адаптер.
6. Проверить предупреждения и сохранённые ссылки на исходные материалы.
7. Получить пользовательское подтверждение перед признанием мигрированных документов актуальной истиной.

MCP запрещает migration source за пределами выбранного workspace. Во встроенном Codex CLI внешний source разрешён только когда пользователь явно назвал его; команды всегда запускаются из целевого project root. Исходная система не удаляется, не перемещается и не переписывается. Архивные записи сохраняются как история.

Автоматическая конвертация не доказывает смысловую эквивалентность заголовков, acceptance criteria и lifecycle. Такие различия проверяются человеком или агентом в отдельном review.
